# Week 9 execution binding

This launcher implements the frozen `week9-factorial-v1` protocol without modifying it. The user authorized fresh B0/M1/M3 evaluations on Feifei and later addition of M2/M4 on 2026-10-09. Each arm receives the fixed stratified-1K panel and clean paired-2000 panel. Full-10K and test remain locked.

`scripts/evaluate_week9.py init` writes an immutable cohort with B0/M1/M3 completed endpoint admissions, exact runtime/package inventory, GPU UUID/driver, CUDA/cuDNN, numerical flags, environment, source and benchmark identities. Every model load and arm run checks this lock. M2/M4 use separate immutable admissions after their already pinned training identities reach the completed epoch-2 endpoint. Admission verifies the policy and full predictor exports, exposure counters and completion chains. It never chooses an intermediate checkpoint.

The legacy LIBERO-Plus and clean JSON protocols are retained byte-for-byte as recording schemas and sources of scene, observation, seed, timeout and state rules. In particular, the clean serializer requires its historical acceptance-rule field. **That field is format metadata only:** neither old BCE model profiles nor Week 4 acceptance decisions execute. Every run identity and HDF5 file explicitly binds the new Week 9 protocol/cohort/admission, `all-action-l1-binary-gripper-v2`, and `legacy_profile_and_acceptance_fields_are_format_only=true`. The actual model factory uses only the pinned fresh all-action-L1 recipe and normalizers. The old clean policy loader and acceptance analysis are not called.

All three initially available arms complete an isolated inference/recording check on the first fixed task of each panel, twice, before any formal Week 9 episode. The wider M3 dev qualification separately sampled every perturbation category and the known lighting mismatch cases. Smoke outcomes do not fill formal panel cells or select checkpoints. Exact input mismatches remain recorded, and whole affected contrasts stay descriptive.

The timing loop preserves the accepted action/observation/termination logic. It synchronizes the GPU immediately before and after each complete policy query. Successful action-query timings are in HDF5; a sealed timing sidecar also retains a failed query with no action transition. Analysis includes those failed query durations, while separately auditing the action-query subset against HDF5. No recorder journal writes occur inside the timed policy call. Model load, episode wall time, evaluation wall time and GPU peaks are separate fields.

Each episode claims a durable attempt before environment creation. At most one infrastructure retry is available, including across restarts. Completed artifacts are recovered without querying again. Policy failures remain failures. Corrupt complete artifacts halt integrity verification; missing/exhausted failures remain in the panel and mark the audit incomplete. Resumption verifies receipt, artifact, timing, metadata and attempt-journal identities.

The queue qualifies B0/M1/M3, then runs B0 perturbed/clean, M1 perturbed/clean and M3 perturbed/clean sequentially. Each panel is followed by artifact-backed interim analysis. The per-panel cap is 48 active hours; the cohort preserves 50 GiB free disk and caps output at 900 GiB. These are operational limits, not checkpoint or outcome selection rules. Queue failure leaves all recordings intact and does not automatically consume additional attempts.

Analysis uses all tasks, common PCG64 resamples, 10,000 draws, seed 7 for perturbed variants and seed 8 for clean task clusters. Ratios pair independent panel draw streams and withhold intervals for any zero denominator draw. Interim tables never impute missing arms. Final factorial estimates require all five complete matrices, and their input qualification is reported separately. The original JEPA exception, historical renderer qualifications, development overlap, parameter/compute differences and single training seed remain limitations.

The source package preserves all files from the accepted shared M3/M4 evaluator unchanged and adds the Week 9 runner, execution/timing helpers, analysis, focused tests and this binding. Model tensors, recorder behavior and the scientific protocol are not patched in an active training or evaluation checkout.

## Pre-rollout runtime initialization correction

The first cohort preparation stopped before any simulator episode or policy query: importing the pinned sensor wrapper imports OpenCV, whose loader prepends its own `cv2/../../lib64` directory to `LD_LIBRARY_PATH`. The launch-time environment had been locked before that import. A staged import probe identified the exact deterministic change; model loading itself did not change that variable. The runner now initializes that same installed OpenCV loader before recording or comparing the effective runtime, verifies its exact location and resulting library path, and pins the TorchInductor cache directory explicitly. No library version, simulator setting, model, task or outcome rule changed.

The unused first cohort and failed launch evidence are retained. The replacement operational cohort is `week9-factorial-v1-cohort02`, under the unchanged scientific protocol. This decision was made before any Week 9 rollout outcome existed. Every arm uses the same initialized runtime lock, still checked again after model loading. Formal launch continues to require all initial arm qualifications.
